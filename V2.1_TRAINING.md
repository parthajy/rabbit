# Rabbit v2.1 Training Plan

## What's broken in v2.0 and why

| Problem | Root cause | Evidence |
|---------|-----------|----------|
| Follow-up answers are fragments or `**` | Only 967 multiturn examples in 82K dataset (1.2%) | Model continues previous answer instead of answering fresh |
| "Summarize what you said" doesn't work | No meta-instruction examples (summarize, rephrase, simplify) | Model trained to answer from memories, not reflect on its own output |
| Temporal reasoning weak ("what changed between X and Y") | No explicit temporal-chain examples | Model dumps all facts, doesn't track progression |
| Causal reasoning missing ("why did X happen") | No cause-effect examples | Model lists events but doesn't connect cause → effect |
| Formatting confusion (outputs raw `**`, `##`) | Trained on 4,124 formatted_answer examples with heavy markdown | Model reproduces training artifacts in wrong contexts |
| Slow (was 2 min, now 5-15s after code fix) | Was 7 LLM calls per question. Now 1. Training isn't the fix. | Code problem, already fixed |

## v2.1 strategy

**Don't retrain everything.** v2.0's 82K base is solid for extraction, triage, summarize, sentiment, importance. The gaps are narrow: multi-turn, meta-instructions, temporal/causal reasoning.

**Add 15K targeted examples on top of the 82K base. Total: ~97K.**

## New training data to generate (15K examples)

### 1. Multi-turn conversations (6,000 examples)

The biggest gap. Currently 967 examples. Need 6x more.

**Format:**
```json
{
  "input": "MEMORIES:\n[1] MEETING: Q2 Planning — Apr 10, 2026\nSummary: Arjun proposed freezing features. Lisa reported 18% recall improvement.\n\n[2] MEETING: Client Sync — Apr 8, 2026\nSummary: NorthBridge escalated delivery delays.\n\nCONVERSATION:\nUser: What happened in recent meetings?\nAssistant: Two key threads emerged. The Q2 planning session on April 10 saw Arjun push for a feature freeze to prioritize stability, while Lisa reported an 18% improvement in recall accuracy [1]. Meanwhile, the NorthBridge client sync on April 8 flagged delivery delays that need attention [2].\n\nUser: What should I prioritize this week?",
  "output": "The NorthBridge delivery delay is the urgent item — client escalations have a shorter fuse than internal roadmap decisions [2]. Get a status update from whoever owns that timeline before your next sync.\n\nThe feature freeze Arjun proposed [1] is important but not time-sensitive — that's a strategic call you can make after stabilizing the client situation.\n\nFollow-up questions:\n- Who is currently handling the NorthBridge delivery timeline?\n- What specific features were on the table before the proposed freeze?\n- Has Lisa's 18% recall improvement been deployed to production yet?\n\nOffers:\n- If you want, I can pull together all NorthBridge-related items across your meetings\n- Do you want me to draft a priority list based on urgency vs importance?"
}
```

**Key requirements:**
- Turn 2+ answers MUST be complete, standalone paragraphs (never fragments)
- Follow-ups reference the conversation naturally but answer independently
- Include these conversation patterns:
  - "Summarize what you just said" / "Can you make that shorter"
  - "Tell me more about [specific detail from previous answer]"
  - "What about [entity mentioned in answer]?"
  - "Actually, focus on [different aspect]"
  - "What should I do about this?"

### 2. Meta-instructions (2,000 examples)

The user talks TO the assistant about its own output. Not trained at all in v2.0.

**Patterns to cover:**
```
"Summarize what you said in 2 sentences"
"Can you simplify that?"
"Say that again but focus on the financial impact"
"Make that into bullet points"
"Who were the people you mentioned?"
"What were the dates you referenced?"
"Rephrase that for my CEO"
"Give me just the action items from your answer"
"You mentioned a risk — elaborate on that"
"Ignore the client stuff, focus on the technical blockers"
```

**Format:** Same as multi-turn. Previous answer in conversation history, meta-instruction as the new question. Output must transform the previous answer as requested.

### 3. Temporal reasoning (2,500 examples)

Track how things change over time across memories.

**Patterns:**
```
"What changed between March and April?"
"How has the funding status evolved?"
"What was decided first, and what changed later?"
"Is this still the plan or did it change?"
"What's the timeline of events for [project]?"
"When did we first discuss [topic] and what's happened since?"
```

**Format:** Memories with dates spanning weeks/months. Output traces the progression chronologically, notes what changed, what stayed, what reversed.

### 4. Causal reasoning (2,000 examples)

Connect causes to effects across memories.

**Patterns:**
```
"Why did the launch get delayed?"
"What led to the client escalation?"
"What caused the budget overrun?"
"What were the consequences of the feature freeze?"
"How did Arjun's decision affect the timeline?"
```

**Format:** Memories contain the cause and effect in separate records. Output connects them with reasoning: "The delay traces back to [cause in memory 1], which triggered [effect in memory 2]."

### 5. Plain answer style (2,500 examples)

Replace the 4,124 formatted_answer + 20,848 answer examples' style. Train the model to write like a knowledgeable colleague, not a markdown report.

**Style rules (bake into every example):**
- No `**bold**` markers, no `## headers`, no markdown formatting
- Natural prose: "Arjun pushed for stability on April 16, but Rohan was still experimenting two days earlier — the team isn't aligned yet."
- Inline citations as [1], [2], [3] — the only formatting allowed
- No "Based on your memories" / "According to your notes" openers
- No "Key Takeaways" / "Summary" / "Conclusion" sections
- End every answer with `Follow-up questions:` and `Offers:` sections

## Data generation plan

### Source material
- 43 real meeting transcripts in `data/seeds/real/` (diverse: SaaS, law firm, manufacturing, NGO, fintech)
- Mix of 3-5 transcripts per example to create realistic multi-memory scenarios
- Vary workspace sizes: some with 3 memories, some with 10+

### Generation method
Use Claude API (or GPT-4) to generate examples:
1. Pick 3-5 random meeting transcripts as "memories"
2. Generate summaries as Rabbit would produce them
3. Generate a question + answer pair
4. Generate 2-3 follow-up turns
5. Generate meta-instruction turns ("summarize that", "focus on X")
6. Validate: no hallucination, citations match, answers are complete

**Cost estimate:** ~$30-50 on Claude API for 15K examples (RunPod $90 credit won't work here — need an LLM API for generation)

### Quality filters (same as v2.0)
- Remove examples where output is <50 chars
- Remove examples where citations reference non-existent memories
- Remove examples with `##` headers or `**bold**` in output
- Remove examples where follow-up answer is a fragment (<100 chars)
- Deduplicate by input hash

## Training config

```python
# v2.1: continue training from v2.0 LoRA
BASE_MODEL = "unsloth/Qwen2.5-32B-Instruct-bnb-4bit"
ADAPTER = "reattend/rabbit-v2.0"  # start from v2.0 weights
OUTPUT = "models/rabbit-v2.1"
HF_REPO = "reattend/rabbit-v2.1"

LORA_R = 32
LORA_ALPHA = 32
EPOCHS = 1  # 1 epoch over the full 97K (82K old + 15K new)
BATCH_SIZE = 1
GRADIENT_ACCUMULATION = 16
LEARNING_RATE = 5e-5  # lower than v2.0's 1e-4 to avoid catastrophic forgetting
MAX_SEQ_LENGTH = 4096  # bump from 2048 — multi-turn needs longer context
WARMUP_RATIO = 0.05
```

**Why continue from v2.0 LoRA:** Starting fresh would lose the extraction/triage/sentiment quality that's already good. Continuing at lower LR adds new skills without forgetting old ones.

**Hardware:** Azure ($1000 credit). 1x A100 80GB, ~10 hours, ~$30-40.
