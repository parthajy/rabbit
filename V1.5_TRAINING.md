# Rabbit v1.5 Training Plan

> Issues found during live deployment (April 11, 2026). Fix via targeted training data.

---

## Issues Found in v1.4

### 1. Summary bleed — model doesn't stop

**Problem:** SUMMARIZE signal produces a good 2-4 sentence summary, then keeps going with `[DETAILED EXPLANATION]`, `[INSTRUCTION]`, or restarts the prompt. The model doesn't know when to stop.

**Example:**
```
"Q1 revenue reached $2.3M, surpassing the target by 15%..."  ← good, stop here
"\n\n[DETAILED EXPLANATION]\nThis summary encapsulates..."    ← bleed, should not exist
"\n\n[INSTRUCTION]\nAs Rab..."                                ← prompt leak
```

**Fix:** Generate 3,000 SUMMARIZE examples where the output is ONLY 2-4 sentences with no trailing text. Add negative examples with `[DETAILED EXPLANATION]` and `[INSTRUCTION]` stripped out. Train the model to produce clean stop points.

**Data needed:** 3,000 examples
**Signal:** SUMMARIZE

---

### 2. Sentiment adds explanation

**Problem:** SENTIMENT signal should return one word (`positive`, `negative`, `neutral`, `tense`, `urgent`) but sometimes adds an explanation after it.

**Example:**
```
"neutral\n\nthe tone here is neutral because the..."  ← should be just "neutral"
```

**Fix:** Generate 2,000 SENTIMENT examples with strict single-word outputs. Vary the content but always output exactly one word with no explanation.

**Data needed:** 2,000 examples
**Signal:** SENTIMENT

**Workaround (already deployed):** Post-processing clips to first word.

---

### 3. Triage type echoes signal name

**Problem:** TRIAGE signal returns `"type": "TRIAGE"` instead of the actual content type (meeting, decision, task, update, etc.).

**Example:**
```
"triage_type": "TRIAGE"   ← should be "meeting" or "report"
```

**Fix:** Generate 3,000 TRIAGE examples with correct type values. Ensure the training data never has "TRIAGE" as the type value.

**Data needed:** 3,000 examples
**Signal:** TRIAGE

---

### 4. Organization hallucination

**Problem:** EXTRACT signal invents organization names when none are mentioned. Produced "Recode" from text that had no organization.

**Example:**
```
Input: "Sarah decided to delay the product launch..."
Output: {"organizations": ["Recode"]}  ← hallucinated, no org mentioned
```

**Fix:** Generate 5,000 EXTRACT examples with a mix of:
- Text WITH organizations → extract them correctly
- Text WITHOUT organizations → return `"organizations": []`
- Emphasis on faithful extraction (only extract what's literally in the text)

**Data needed:** 5,000 examples
**Signal:** EXTRACT

---

### 5. Tags echo signal prefix

**Problem:** Tags array includes the signal prefix like `"TRIAGE"` as a tag.

**Example:**
```
"tags": ["TRIAGE", "Revenue", "Sales Success", ...]  ← "TRIAGE" is not a tag
```

**Fix:** Include in TRIAGE training data examples where tags are always lowercase, descriptive, and never include signal names.

**Data needed:** Included in TRIAGE fix above (3,000 examples)
**Signal:** TRIAGE

---

### 6. Answer date hallucination

**Problem:** ANSWER signal invents dates for citations. Sources section says "March 10, 2023" when no such date was in the memories.

**Example:**
```
Sources:
[1] Postponement, March 10, 2023 — Sarah's decision  ← date was never in the input
```

**Fix:** Generate 3,000 ANSWER examples where sources citations use only dates/info from the actual memory context provided. If no date is available, use "Date unknown" or omit.

**Data needed:** 3,000 examples
**Signal:** ANSWER

---

### 7. Answer adds fictional context

**Problem:** ANSWER signal adds context the model made up — e.g., calling the company "a fintech startup like Reach" when no such info exists in memories.

**Fix:** Same as #6 — train with examples that strictly use only provided memory context, never invent industry, company name, or background.

**Data needed:** Included in ANSWER fix above (3,000 examples)
**Signal:** ANSWER

### 8. Retrieval bias toward high-importance memories

**Problem:** When asking about a specific person/topic, the model returns answers about a different, higher-importance memory instead. Retrieval ranking over-weights importance score, drowning out the actually relevant memory.

**Example:**
```
Question: "What do you know about Priya?"
Answer: talks about Sarah (importance 4) instead of Priya (importance 5 but less keyword match)
```

**Fix:** This is partly a retrieval issue (tune importance weighting in hybrid search) and partly an ANSWER training issue. Generate 2,000 ANSWER examples where the model must answer about the specific entity asked about, even when other higher-importance memories are in context.

**Data needed:** 2,000 examples
**Signal:** ANSWER + retrieval tuning
